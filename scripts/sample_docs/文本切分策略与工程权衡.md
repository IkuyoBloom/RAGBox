# 文本切分策略与工程权衡

## 一、切分为什么是 RAG 的关键环节

检索增强生成的效果上限由「检索到的上下文质量」决定，
而上下文质量在很大程度上被切分策略决定。切分不当会造成两类典型失败：

- **语义割裂**：一个完整的论述被切断在两片之间，
  两片各自都缺乏完整信息，检索时都难以被匹配到，
  或者匹配到了也无法支撑回答。
- **噪声稀释**：切片过大，一个片段里混入多个无关主题，
  向量表示被平均化而失去区分度，同时挤占了宝贵的上下文窗口。

## 二、常见切分方法

### 2.1 固定长度切分

按固定字符数或 token 数机械切分，实现最简单、速度最快。
缺点是几乎必然在句子或段落中间断开。仅适用于对语义完整性要求极低的场景。

### 2.2 递归字符切分

按一组**优先级递减**的分隔符依次尝试：先按段落分，
段落仍过长则按句号分，再长则按逗号分，最后才硬切。

这一策略的直觉是：作者用段落和标点表达的语义边界，
比字符计数更能反映内容结构。它是目前最常用的基线方法。

对于中文，分隔符优先级需要专门设计。
若沿用英文的 `\n\n` / `\n` / 空格 / 空串 这一套，
中文文档会直接退化到「按空格切」，而中文句子之间没有空格，
最终等价于硬切，效果很差。正确做法是把中文标点
（。！？；，、）按语义强度插入到优先级序列中。

### 2.3 语义切分

用嵌入模型计算相邻句子的向量相似度，在相似度骤降处切分，
认为那里是语义边界。

效果通常优于递归字符切分，但需要对全文逐句编码，
索引阶段的计算开销显著增加。且相似度阈值需要按语料调参。

### 2.4 结构化切分

利用文档自身的结构信息：Markdown 标题层级、PDF 的章节树、
代码的函数边界、表格的行列关系。

这是信息损失最小的方式，但要求解析阶段能可靠地还原结构，
而这在 PDF 上往往很难保证。

## 三、重叠（Overlap）的作用与代价

相邻切片之间保留一段重叠文本，是缓解语义割裂的标准手段。
典型设置是切片长度的 10% 至 20%。

重叠的效果是双面的：

- **收益**：跨边界的信息至少在其中一片里是完整的，
  降低了「答案被切断」的概率。
- **代价**：同一段文本被索引多次，存储与向量化的开销按重叠比例增加；
  更重要的是，重叠部分会让相邻切片高度相似，
  检索时可能同时返回多个几乎重复的片段，挤占 Top-K 名额，
  降低上下文的实际信息密度。

因此重叠比例不是越大越好，需要在「避免割裂」与「减少冗余」之间取舍。

## 四、段落边界应当作为硬约束

一个容易被忽视的实践细节：把一个长文档先按段落拆开，
让每个段落成为不可跨越的边界，再在段落内部做递归切分，
最后把过短的相邻片段**打包合并**到接近目标长度。

这样做的理由：

1. 段落是作者明确划定的语义单元，跨越段落合并容易产生主题混杂的切片；
2. 缺少「打包」这一步时，由大量短段落组成的文档会切出数十个十几字的碎片，
   检索时 Top-K 全被这些碎片占满，真正有信息量的长切片反而进不来。

## 五、切片长度如何选择

切片长度没有普适最优值，需要结合三个因素：

- **嵌入模型的训练分布**：多数文本嵌入模型在 256 至 512 token 的片段上训练，
  远超这个长度时向量表示的区分度会下降。
- **问题的粒度**：事实型问题（某个参数是多少）适合小切片；
  综述型问题（这篇文章的主要贡献）需要大切片或跨切片聚合。
- **生成模型的上下文窗口**：窗口越大，可以容纳越多切片，
  但同时也更容易引入无关内容干扰生成。

常用做法是取 300 至 800 字符作为起点，
用真实问题集做小规模评估后再调整，而不是凭直觉设定。
