# BM25 检索算法详解

## 一、从 TF-IDF 到 BM25

TF-IDF 用「词频 × 逆文档频率」衡量词对文档的重要性，但它有两个明显缺陷：

1. **词频无饱和**：一个词出现 100 次的重要性被判为出现 10 次的 10 倍，
   这不符合直觉 —— 词出现到一定次数后，其区分能力的增长应趋于平缓。
2. **无文档长度归一化**：长文档天然包含更多词、更高的词频，
   会系统性地压过短文档，而长并不等于更相关。

BM25（Best Matching 25）针对这两点做了修正，成为稀疏检索的事实标准。

## 二、评分公式

对查询 Q 与文档 D，BM25 的评分为查询中各词项贡献之和：

    score(D, Q) = Σ_{t ∈ Q} IDF(t) · [ f(t,D)·(k1+1) ] / [ f(t,D) + k1·(1 - b + b·|D|/avgdl) ]

各符号含义：

- `f(t,D)`：词项 t 在文档 D 中的出现次数（词频 TF）。
- `|D|`：文档 D 的长度（词数）；`avgdl`：语料平均文档长度。
- `k1`：词频饱和参数，通常取 1.2 至 2.0。
- `b`：文档长度归一化强度，取值 0 至 1，通常取 0.75。

## 三、两个参数在做什么

### 3.1 k1 控制饱和速度

当 `k1 = 0` 时，整个分式退化为 1，词频完全不起作用（退化成二值模型）。
`k1` 越大，词频的影响越强、饱和越慢。

从极限看：当 `f(t,D) → ∞` 时，分式趋近于 `k1 + 1`，
即无论词出现多少次，其贡献都有上界。这正是「饱和」的含义。

### 3.2 b 控制长度归一化的强度

- `b = 0`：完全不做长度归一化，长文档占优。
- `b = 1`：完全归一化，长短文档一视同仁。
- `b = 0.75`：折中，是多数语料上的经验最优值。

分母中的 `1 - b + b·|D|/avgdl` 是一个相对长度因子：
文档长度等于平均长度时该因子为 1，此时分母退化为 `f + k1`。

## 四、IDF 的几种变体

经典 BM25 的 IDF 形式为：

    IDF(t) = ln( (N - n(t) + 0.5) / (n(t) + 0.5) )

其中 N 为文档总数，`n(t)` 为包含词项 t 的文档数。

两个需要注意的工程细节：

1. **负 IDF 问题**：当某词出现在超过半数文档中时，上式会得到负值。
   负 IDF 意味着「出现该词反而降低相关性」，这在直觉上不合理，
   会导致 BM25 给匹配到的文档扣分。
   常见处理是取 `max(0, IDF)`，或在 IDF 上加一个正的偏移量。
   实践中对高频词做停用词过滤，也能缓解这一问题。
2. **未命中词的处理**：检索时通常直接跳过 `f(t,D) = 0` 的文档，
   而不是遍历全部文档计算 0 分，这是倒排索引能做到高效的原因。

## 五、BM25 的适用边界

**擅长**：

- 专有名词、型号、编号、代码标识符等字面量查询；
- 需要精确匹配术语的场景；
- 可解释性要求高、需要给出打分依据的场景；
- 无需训练、无 GPU 依赖、延迟极低（纯内存计算，通常在毫秒级）。

**不擅长**：

- **词汇鸿沟**：用户问「优化算法」，文档写的是「梯度下降」，
  两者无共同词项时 BM25 完全无法匹配。
- 同义改写、跨语言检索、语义相近但用词不同的情况。
- 中文等无空格语言需要额外的分词步骤，分词质量直接影响效果。

## 六、中文场景的分词要点

中文没有天然词边界，BM25 依赖的分词步骤会带来额外的不确定性：

- **分词粒度**：过粗会漏召回（「神经网络」切不出「网络」），
  过细会引入大量单字噪声（「梯度下降法」被切成单个汉字后，
  与「梯子」「下降趋势」产生虚假匹配）。
- **索引与查询一致性**：两侧必须使用同一套分词规则，
  否则词表不对齐，匹配率会显著下降。
- 搜索引擎模式（如 jieba 的 `lcut_for_search`）会在长词之外额外输出子词，
  提升短查询的召回，代价是词频统计被放大。

## 七、在混合检索中的位置

由于 BM25 与稠密向量检索的失败模式互补，
将二者结合是当前的主流方案。融合时需要注意：

两者的分数量纲完全不同 —— BM25 是无上界的对数加权和，
向量相似度是 0 至 1 的有界值。直接加权求和需要先归一化并反复调参，
且换用不同的嵌入模型后往往需要重新调整权重。

只使用**排名**信息的倒数排名融合（RRF）可以规避这一问题，
这使其成为工程上更稳健的选择。
