# 大语言模型幻觉的成因与缓解

## 一、什么是幻觉

幻觉（Hallucination）指模型生成了与事实不符、或与给定输入不一致的内容，
且**以与正确回答相同的流畅度和自信度呈现**。

这个「自信」特征使幻觉格外危险：用户无法仅凭语气判断可靠性，
必须依赖外部核查手段。

幻觉通常分为两类：

- **事实性幻觉**：生成的内容与世界事实不符，例如编造不存在的论文、作者或数据。
- **忠实性幻觉**：内容本身可能是真的，但与给定的输入（如检索到的资料）不一致，
  或超出了输入所支持的范围。

在检索增强生成系统中，第二类更为关键 —— 因为系统已经提供了参考资料，
模型仍可能忽略资料而依据自己的参数化记忆作答，这直接违背了 RAG 的设计初衷。

## 二、成因

### 2.1 训练目标与事实性的错位

自回归语言模型的训练目标是最大化下一个 token 的似然，
即「生成看起来合理的文本」，而不是「生成真实的陈述」。
流畅性与真实性在目标函数中并无必然联系。

### 2.2 长尾知识的稀疏性

训练语料中高频出现的知识被充分学习，而低频、专业、时效性强的知识
在参数中只有极弱的表征。当被问及这类内容时，
模型倾向于用相似的高频模式去「填空」，从而产生看似合理实则错误的回答。

### 2.3 解码策略的影响

采样温度越高、top-p 越宽松，模型越容易偏离高概率路径，
幻觉风险随之上升。贪心解码虽然更保守，但会牺牲多样性。

### 2.4 上下文冲突

当检索到的资料与模型的参数化知识冲突时，
模型并不总是优先采信上下文。研究表明，
冲突内容的呈现位置、措辞强度都会影响模型的选择倾向。

## 三、缓解手段

### 3.1 提示层面的约束

在系统提示中明确要求「只依据提供的资料作答」，
并要求在资料不足时明确说明而非猜测。
实验表明这类指令能显著降低编造率，但对能力较弱的模型效果有限。

更强的手段是**要求标注来源编号**：模型必须为每个结论指出
它依据的是第几段资料。这不仅让答案可核查，
也通过「必须能指出来源」这一约束抑制了凭空生成。

### 3.2 检索层面的改进

幻觉的根源常常在检索而非生成。若关键信息没有被召回，
模型要么拒答，要么用先验知识填补。因此提升召回质量
（混合检索、重排序、查询改写）本身就是最有效的抗幻觉手段。

### 3.3 解码层面的控制

降低温度、限制生成长度、使用重复惩罚，
都能减少模型「自由发挥」的空间。代价是回答的多样性下降。

### 3.4 后验校验

生成后再做一次核查：把答案拆成若干原子陈述，
逐条判断是否被上下文所支持，被判定无支撑的陈述予以删除或标注。

这一方法效果直接，但需要额外一次模型调用，延迟与成本翻倍。

## 四、如何度量幻觉

- **忠实度（Faithfulness）**：答案中的陈述被检索上下文支持的比例。
  这是 RAG 场景下最核心的指标。
- **答案相关性（Answer Relevancy）**：答案是否切题，
  是否存在答非所问或冗余。
- **引用准确率**：标注的来源编号是否真的包含所引述的内容。
  仅检查编号是否越界是不够的，还需要判断内容是否匹配。

由于人工标注成本高昂，实践中常用大语言模型作为评判者（LLM-as-a-Judge）。
但需注意，以模型评判模型存在系统性偏置 ——
评判模型可能偏好与自己生成风格相似的答案，
也可能在长文本判断上失准。因此自动化指标应与抽样人工校验结合使用。

## 五、工程上的务实结论

对于面向专业资料的知识库问答系统，
**「宁可拒答，不可编造」应当作为默认策略**。
一次明确的「根据现有资料无法回答」，其价值远高于一次听起来合理但错误的回答，
因为前者会促使用户去补充资料，而后者会直接误导决策。
